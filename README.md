# text-self-review

**迭代式文本自查流程（RCAI 循环）**

面向事实密度高、需对外交付的文本——审稿意见、论文稿件、综述、调研报告、汇报讲稿、对外邮件。
用「换维度」而不是「再读一遍」的方式，逼出单轮自查必然留下的盲区。

---

## 一句话

> **迭代的收益不来自「重复」，而来自「换角度」。**
> 每轮必须带来一个此前没查过的维度，否则只是把同一张网撒第二遍。

## 核心命题

**单轮自查必然留盲区，而盲区的形状由当轮采用的维度决定。**

同一份文本，用「对源文件的事实忠实度」查一遍、再用「外围事实源」查一遍，捞到的东西几乎不重叠。
所以问题从来不是「查得够不够仔细」，而是「**这一轮和上一轮，用的是不是同一张网**」。

---

## 这套流程是怎么来的

不是设计出来的，是**归纳出来的**。

一份约 1300 词的外部评议文本，四轮自查的实际修正数：

| 轮次 | 采用的维度 | 修正数 | 最严重的发现 |
|---|---|---|---|
| 一 | 文本对源文件的事实忠实度 | 10 | 要求对方做一件他早已说明过的事 |
| 二 | 曲解原意 / 过度概括 / 逻辑跳跃 / 未检验断言 | 8 | **上一轮的「修正」本身改错了** |
| 三 | 参考文献著录 / 语言质量 / 体例 | 9 | 参考文献标题系虚构 |
| 四 | 独立第三方审查 + 复核 | 9 | 摘要与结果段自相矛盾（前三轮都没看摘要）|

三条从数据里长出来的教训：

1. **第二轮的错，是第一轮「修」出来的。** 修正本身产出新文本，必须接受同等强度的审查。
2. **第三轮才想起查参考文献。** 前两轮注意力全在「对源文件的忠实度」上——而参考文献是**另一个事实源**。
3. **第四轮才发现摘要问题。** 不是没看，是**没把它当成一个独立的维度**。

## 用法

把整个目录放进 skills 目录，或者直接读 `SKILL.md`。

```
SKILL.md                          流程入口：骨架、三条纪律、收敛判据、实证纪律
references/dimensions.md          23 个自查维度 + 6 个高产出维度的详解
references/convergence.md         四轮实证数据、收敛判据、止损、留痕
references/independent-review.md  引入独立视角时的隔离纪律
scripts/number_diff.py            跨版本数字一致性比对
evals/evals.json                  测试用例（触发场景 + 预期行为）
```

遵循 Agent Skills 规范：`SKILL.md` frontmatter 含 `name` / `description` / `compatibility`，
`name` 与目录名一致，正文按需经 `references/` 逐层加载。

## 适用与不适用

**适用**：有源可查、需对外交付、错一处会伤可信度的文本。

**不适用**：
- 纯创意写作（那是另一套逻辑）
- 没有事实锚点的文本——`D1–D12` 全部依赖「有一份源文件可回查」
